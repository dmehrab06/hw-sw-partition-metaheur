\section{Introduction}
Hardware/software co-design seeks a division of functionality between programmable software and specialized hardware such that the resulting system meets performance, area, and communication constraints. In practice, that division is usually represented as a binary labeling over a task graph: some tasks remain in software for flexibility, while others move to hardware for acceleration. The challenge is that the quality of a partition is determined not only by local node costs but also by how that partition changes the eventual schedule. When a task is moved to hardware, it may shorten its own execution time while simultaneously increasing communication overhead or creating new serialization effects on the software lane. For this reason, partitioning and scheduling are tightly coupled even when they are implemented in separate software modules.

The literature reviewed in the 2021 paper by Zheng \textit{et al.} argues that exact methods such as integer linear programming, dynamic programming, and branch-and-bound are valuable on small instances but become too expensive for large graphs \cite{zheng2021}. Metaheuristics such as genetic algorithms, simulated annealing, particle swarm optimization, and related hybrids enlarge the feasible problem size, yet their search still depends on repeated black-box evaluation of discrete candidates. The same paper introduced a graph-convolution-based partitioner, GCPS, to accelerate the search by learning node-level decisions from graph structure and then using schedule feedback to refine them \cite{zheng2021}. That idea is compelling because HW/SW partitioning is naturally a node-level decision problem on a directed acyclic graph (DAG).

The current repository continues in that direction but moves from a mostly heuristic GCN pipeline toward a more explicitly differentiable optimization framework. Two implementations are especially relevant:
\begin{itemize}
\item \texttt{diff\_gnn\_utils\_schedule.py}, which implements a differentiable graph-neural partitioner without explicit ordering heads.
\item \texttt{diff\_gnn\_ordering.py}, which augments the model with ordering logits, soft permutations, and an order-aware makespan surrogate.
\end{itemize}

The baseline model already goes beyond a naive classifier. It constructs task features from software time, hardware time, area, degree, and paper-inspired gain descriptors; relaxes binary placement through sigmoid or straight-through sampling; optimizes a soft longest-path loss; and then repairs the decoded solution so it respects area constraints. The ordered model adds a second idea: if software tasks are serialized and hardware tasks may also compete for precedence structure, then the model should not learn only \emph{where} tasks go but also \emph{in what relative order} they are likely to execute.

This observation is also consistent with the internal 2025/2026 draft in the repository, which places substantial emphasis on makespan-based objectives such as OPTM, communication-aware scheduling, critical-path list scheduling, event-driven simulation, and shortest-processing-time heuristics. That draft frames the benchmark task graphs as DAGs derived from neural-network models and evaluates candidate partitions through both proxy partition costs and schedule-based objectives. The current repository code mirrors that perspective: discrete solutions can be judged either by a queue-style simulator or by a legacy linear-programming-based makespan evaluator, and additional scheduling heuristics are already implemented in \texttt{utils/scheduler\_utils.py}.

The purpose of this paper is therefore twofold. First, it documents the current differentiable GNN pipeline in paper form, emphasizing the difference between the baseline partition-only model and the order-aware extension. Second, it provides a concrete formatting scaffold that can later be rewritten manually into a non-AI final manuscript. To support that goal, the paper intentionally uses repository-grounded descriptions and a small set of already available result artifacts rather than inventing a fully new experimental campaign.

The main contributions of this draft are as follows:
\begin{itemize}
\item It formalizes the repository's current HW/SW partitioning problem in a way that is consistent with both the 2021 GCPS paper and the newer internal experiment draft.
\item It explains the baseline differentiable placement model and the ordered extension in a unified notation, highlighting exactly what changes when ordering is introduced.
\item It demonstrates how to present repository-derived results in a paper narrative, including both positive and negative evidence, rather than forcing a one-sided conclusion.
\end{itemize}

The rest of the paper is organized as follows. Section II defines the partitioning and scheduling problem. Section III summarizes related work. Section IV presents the proposed differentiable graph-neural method and the ordered extension. Section V discusses repository-derived experimental results and how they may be presented in a final paper. Section VI concludes, and the appendix maps the paper claims back to implementation artifacts and default settings.
